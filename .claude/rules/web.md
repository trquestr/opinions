# Фронт: Next.js 16 (`apps/web`)

Источники: Next.js docs v16 — Data Security, Content Security Policy, Backend for Frontend, Error Handling,
Testing (Vitest), Production Checklist. Сверять через context7 `/vercel/next.js/v16.x`.

## SSR и SEO — главное требование

- Всё, что должно индексироваться (тексты, заголовки, ссылки, списки мнений), рендерится **на сервере**.
  Не загружать контент в `useEffect` / клиентским `fetch`.
- Server Components по умолчанию. `"use client"` — только на листьях, где нужна интерактивность; не на layout/page целиком.
- У каждой страницы — `metadata` или `generateMetadata`: уникальные `title`, `description`, `alternates.canonical`, OpenGraph.
  Новую публичную страницу — добавить в `app/sitemap.ts`. Один `h1` на страницу, семантические теги.
- Динамические страницы мнений/вопросов — пререндер или ISR, где возможно; полный динамический рендер — только если
  контент зависит от запроса.
- Ссылки — `next/link`, картинки контента — `next/image` с `alt` и размерами (без CLS).

## Безопасность

- Доступ к данным и секретам — только в серверных модулях с `import 'server-only'` (Data Access Layer).
  Клиентский компонент получает готовый минимальный DTO, а не запись из БД/API.
- Server Actions и Route Handlers — публичные эндпоинты: в каждом валидировать вход (zod) и заново проверять
  аутентификацию и права, не полагаясь на то, что страница защищена.
- Входящие заголовки (Cookie, Authorization) не пробрасывать в исходящие запросы и в ответ без явной нужды.
- Заголовки безопасности и CSP — в `security-headers.ts` (подключены в `next.config.ts`). CSP ослаблять только
  осознанно и с комментарием. Сейчас `script-src 'unsafe-inline'`, потому что страницы пререндерятся статически
  (nonce требует динамического рендера на каждый запрос).
- Внешние скрипты с CDN не подключать: класть в `public/` с закреплённой версией.
- `dangerouslySetInnerHTML` — только для JSON-LD (`JSON.stringify` от своих данных), больше нигде.

## Отказоустойчивость

- `error.tsx` на сегментах, где может упасть загрузка данных; `global-error.tsx` и `not-found.tsx` — в корне.
  Пользователю — понятное сообщение и «Попробовать снова»; в лог — `error.digest` для связи с серверными логами.
- Запросы к `apps/api` с сервера — через один клиент-модуль с таймаутом (`AbortSignal.timeout`), обработкой
  не-2xx и валидацией ответа схемой. Необязательный блок упал — страница рендерится без него (Suspense + фолбэк).
- Старые WebGL-модули героя грузятся только через `app/landing-scripts.tsx` после гидрации (см. `hero.md`).

## Производительность

- Минимум клиентского JS: не тащить библиотеки в клиентский бандл ради мелочи; тяжёлое — `next/dynamic`.
- Шрифты — локальные, `preload` только критичного. Картинки — `next/image` (кроме статичного декора героя).
- Кэширование — через `cacheComponents` / `"use cache"` с явным `cacheLife` и тегами для инвалидации.
- Core Web Vitals — требование: LCP < 2.5 с, CLS < 0.1, INP < 200 мс на мобильном.

## Тесты

- Vitest + Testing Library (`*.test.tsx` рядом с кодом). Синхронные компоненты, хуки, утилиты, `metadata`,
  `robots`/`sitemap`, заголовки безопасности — unit-тестами.
- Async Server Components Vitest не поддерживает — их проверять E2E (Playwright, когда появится).
- Покрытие ≥ 80% (`yarn workspace web test:cov`).
