# Общие правила кода

Основа: OWASP Top 10:2025, OWASP Node.js и REST Security Cheat Sheets, AWS Builders' Library
(«Timeouts, retries and backoff with jitter»), официальные доки Next.js 16 и NestJS 12. Адаптировано под «Мнения».
Четыре требования владельца, в порядке приоритета: **безопасно → устойчиво к отказам → покрыто тестами → эффективно**.

## Документация

- Перед кодом с API библиотеки — **context7** (`resolve-library-id` → `query-docs`), с версией из lock-файла
  (Next `/vercel/next.js/v16.x`, Nest — `/websites/nestjs`). Своей памяти про API Next 16, Nest 12, React 19 не доверять.
- Next дополнительно кладёт доку своей версии в `node_modules/next/dist/docs/`; Nest — https://docs.nestjs.com/llms.txt.
- Не нашлось в доке — так и сказать, а не угадывать сигнатуру. Проверить по `.d.ts` в `node_modules`.

## TypeScript

- `strict` не ослаблять. Без `any` (нужно — `unknown` + сужение), без `as` для «заглушки» типов, без `!` non-null.
- Внешние данные (запрос, env, ответ чужого API, `localStorage`, `JSON.parse`) — `unknown` до валидации схемой (zod).
- Типы выводить из схем (`z.infer`), а не дублировать руками.
- Чистые функции и маленькие модули; побочные эффекты — на краях (контроллер, route handler, `main.ts`).

## Безопасность

- **Доверия нет никому снаружи**: каждый вход валидируется схемой на границе — allowlist полей, длины, форматы.
  Лишние поля отклонять, не игнорировать молча.
- **Доступ проверяется на каждом эндпоинте и на каждом объекте** (A01, IDOR): не «страница уже защищена», а
  «этот пользователь может это действие над этим id».
- **Fail closed** (A10): ошибка проверки прав или конфига = отказ, а не пропуск.
- Секреты — только из env, валидируются на старте; никогда в коде, логах, URL, ответах, клиентском бандле.
  На фронте в браузер попадает только `NEXT_PUBLIC_*` — туда секреты не класть.
- Наружу — без стеков и внутренних сообщений; в лог — подробности с id корреляции.
- Нет `eval`, `new Function`, `child_process` с пользовательским вводом, `dangerouslySetInnerHTML` с непроверенным HTML.
- Запросы к БД — только параметризованные (ORM/query builder), никакой склейки строк.
- Cookie с сессией — `HttpOnly`, `Secure`, `SameSite=Lax|Strict`. Токены не в URL.
- Зависимости (A03): только с решения владельца, точные версии в `yarn.lock`, `yarn install --immutable` в CI,
  `yarn npm audit` в CI. Внешние скрипты с CDN — не подключать, класть в `public/` с закреплённой версией.

## Устойчивость к отказам

- **Таймаут на каждый исходящий вызов** (HTTP, БД, очередь): `AbortSignal.timeout(ms)` для `fetch`. Без таймаута — баг.
- **Ретраи** — только для идемпотентных операций и только на временные сбои (сеть, 5xx, 429), не на 4xx;
  с лимитом попыток, экспоненциальным backoff с потолком и jitter; ретраить на одном уровне стека, не на каждом.
- Неидемпотентные записи, которые могут повториться (оплата, создание сущности по кнопке) — с ключом идемпотентности.
- Деградация вместо падения: недоступна необязательная зависимость — отдать частичный ответ/фолбэк и залогировать.
- Не глотать ошибки: `catch` либо обрабатывает осмысленно, либо пробрасывает с контекстом (`new Error(msg, { cause })`).
  Пустой `catch {}` запрещён. Промисы не бросать без `await`/`.catch` (floating promises).
- `uncaughtException`/`unhandledRejection` — не «чинить» и продолжать: залогировать и дать процессу упасть,
  перезапустит супервизор. Graceful shutdown на SIGTERM — закрыть сервер и соединения.
- Ресурсы ограничены: размер тела запроса, размер страницы выборки (пагинация обязательна), rate limit.

## Тесты

- Новый код — с тестами в том же изменении. Исправленный баг — сначала падающий тест, потом фикс.
- Порог покрытия — 80% по строкам/веткам/функциям (настроен в `vitest.config.*`); понижать порог нельзя.
- Тестировать поведение, а не реализацию: вход → выход, HTTP-запрос → ответ, рендер → что видит пользователь.
- Обязательно покрывать: невалидный вход, отказ в доступе, сбой зависимости (таймаут/ошибка), граничные значения.
- Внешние зависимости в тестах — подменять (`overrideProvider`, моки `fetch`), сеть в unit-тестах не ходит.
- Тест не ослаблять, чтобы он прошёл (`skip`, `only`, расширить `expect`, поднять таймаут) — чинить код или
  явно согласовать с владельцем.
- Тесты детерминированы: без реального времени (`vi.useFakeTimers`), без зависимости от порядка запуска.

## Эффективность

- Сначала измерить, потом оптимизировать; но очевидные вещи — сразу: без N+1 запросов, без последовательных
  `await` у независимых вызовов (`Promise.all`), без синхронного I/O и тяжёлых вычислений в обработчике запроса.
- Выборки — с пагинацией и только нужными полями. Индексы — под реальные запросы.
- Кэшировать осознанно: явный TTL и инвалидация, никаких «вечных» кэшей в памяти процесса без лимита.

## Стиль

- Комментарии по-русски, объясняют «почему», а не «что». Шейдеры и физика — подробно, с формулами.
- Имена — по смыслу предметной области (мнение, вопрос, ответ), без сокращений.
- Логи — структурированные, без персональных данных.
